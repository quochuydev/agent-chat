## Visual style — v0-style workspace

A neutral, monochrome workspace: a thin top **Toolbar**, a narrow left
**activity log + composer**, and a large right **preview canvas** that shows
the latest (or selected) job's full output. Palette is grayscale — near-black
ink (`#171717`), muted labels (`#8f8f8f`), hairline borders (`#ededed`),
`#fafafa` canvas — with a single black action color for Send.

Left **job rows** are static breadcrumbs (icon + label + status dot); clicking
one selects it in the preview. The preview defaults to the **latest** job and
is the only live poller (one `useJob` per visible card). Sending a message
resets the selection to `null` so the canvas follows the newest output.

## Mobile (< md) — single pane + drawer

The preview canvas is hidden; the activity log fills the screen. The Toolbar's
☰ (or the title) opens the **ConversationList** as an overlay drawer with a
dimmed backdrop.

## Data flow (today — async jobs + live polling)

```mermaid
flowchart TD
    I[input + Enter] --> SV[ChatView.send]
    SV --> OC[onChange: append user msg]
    OC --> SH[ChatShell debounced PUT → /api/conversations Postgres]
    SV -->|POST /api/chat| RT[route.ts agent loop]
    RT --> RS["{ message, jobs, suggestions }"]
    RS --> AP[onChange: append assistant msg + JobRef[]]
    AP --> JC[render JobCard queued]
    JC --> PL{poll connector /jobs/{id}}
    PL -->|running| UP[update bar] --> PL
    PL -->|done| VP[show gallery / audio / project]
    PL -->|failed| ER[error + retry]
    PL --> SC[auto-scroll + refocus input]
```

State lives in `ChatShell`; `ChatView` is controlled (`messages` + `onChange`).
No store, no socket — one `fetch` per turn, then per-job polling.

## Persistence

Conversations + messages live in **Neon Postgres**, Clerk-user-scoped
(`/api/conversations`, `lib/db-conversations.ts`). Saves are debounced 500ms
per conversation. localStorage holds only UI prefs: `chatWidth` (pane width),
`imageProvider` (FLUX vs Imagen), `agentchat:apiUrl` (connector base).

## Connector access from the browser

The browser calls the connector **directly** at `http://localhost:3333`
(CORS allows localhost + the hosted app). The user's backend runs on their own
machine, so only they can reach it; override with `?apiUrl=` (remembered).
`lib/connector.ts` (`connectorUrl`, `useApiBase`) is the single helper;
`/api/jobs/{id}/[...rest]` is a same-origin fallback proxy when no base is set.

## Types it renders (lib/types.ts)

```
DisplayMessage = { role, content, jobs?: JobRef[], suggestions?: string[] }
JobRef         = { id, tool, status }
ChatResponse   = { message, jobs: JobRef[], suggestions?: string[] }
Job            = { id, tool, status, progress, result, error }
```

## Channels, voices, providers

- **Channels** (`lib/channels.ts`): per-niche script voice + art style —
  pick one on a fresh chat; rides along on the next `/api/chat` call.
- **Voices**: Kokoro voice ids; `VoiceSample` plays `/voice/sample` cached
  previews so users can hear a voice before generating.
- **Image backend** (`lib/image-providers.ts`): FLUX (local, free) or Imagen
  (cloud); sent as `provider` on the next `/images` call.

## UI rules (enforced — see CLAUDE.md)

```
every <button>/<a>/onClick element → cursor-pointer
disabled → disabled:cursor-not-allowed (keep, don't drop cursor)
no system icons → SVG (lucide-react)
```

All interactive chrome complies: Toolbar buttons, JobRow, composer icons, the
Send/Dictate circle (cursor-pointer ↔ cursor-not-allowed), and JobCard actions.
